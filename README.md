# MailDesk

## Нативное приложение — Rust + GPUI

MailDesk 2 открывает отдельное нативное окно. CSV, DeepSeek, SMTP, обычные письма с несколькими адресатами, вложения и два подтверждения отправки доступны в приложении. Проекты JSON совместимы с веб-версией; подключения и компании из прежнего профиля сохраняются.

## Локальная веб-версия — Go

Небольшое локальное приложение для подготовки и ручной отправки деловых писем. Один исполняемый файл содержит сервер и интерфейс. Для пользователя не нужны Python, Node.js, Go или установка пакетов: запускаете приложение, оно открывает браузер. Интернет нужен для DeepSeek и SMTP.

Общие сборки не содержат ни паролей, ни списка компаний. Персональный архив, если подготовлен отдельно, содержит `maildesk.env` и `companies.csv` рядом с приложением. Они автоматически загружаются при первом запуске. Для обмена рабочей базой используйте **Экспорт → Проект JSON**: он не содержит паролей.

## Работа

### Обычное письмо

Нажмите **Написать** или **Написать письмо** в меню. Укажите одного или нескольких получателей в **Кому**, тему и текст; добавьте файлы через **Прикрепить файлы**. Адреса разделяются запятой, точкой с запятой или переносом строки, повторяющиеся адреса объединяются. Максимум — 100 адресатов; все они видят общий список «Кому».

**Сохранить черновик** добавляет письмо в общий список, сохраняя текст, адресатов и вложения. **К подтверждению отправки** сохраняет черновик и открывает первый из двух шагов подтверждения. Письмо уйдёт только после последнего подтверждения. Для нового обычного письма можно использовать уже встречавшийся адрес; отметки об отправке других писем при этом сохраняются.

### Письма компаниям

1. В **Подключения** задайте SMTP: для Mail.ru `smtp.mail.ru`, порт `465`, **SSL / TLS**, логин и адрес отправителя, пароль приложения Mail.ru. Добавьте ключ **DeepSeek**. Сохраните. Кнопка проверки SMTP проверяет TLS и авторизацию, **без отправки письма**.
2. В **Шаблон письма → Наша компания и предложение** укажите факты об отправителе: название, продукты, услуги, преимущества, контакты. В **Задание для DeepSeek** задайте цель, тон и подпись. Эти поля передаются модели вместе с описанием компании-получателя. SMTP-настройки не сообщают модели, чем занимается ваша компания; неизвестные факты о вас модель придумывать не должна.
3. Загрузите CSV: обязательные заголовки `Company`, `Email`; описание из `Overview`, `Description`, `Company description`, `Описание` или `Описание компании`. Также читаются `Website`, `City`, `Industry`. UTF-8, запятая или точка с запятой, BOM и переносы внутри кавычек поддерживаются. Лимит — 20 МБ / 10 000 строк за импорт, 20 000 компаний в проекте. Файлы из Excel в другой кодировке нужно сохранить как **CSV UTF-8**. Повторный импорт CSV обновляет непустые описания неотправленных компаний, сохраняя черновики и вложения. Описание можно исправить в редакторе письма, раскрыть **Описание компании**, затем сохранить.
4. Выделите компании и нажмите **Подготовить письма**. Если есть описание, DeepSeek (`deepseek-chat`) получает его, сведения о вашей компании и задание автора. Инструкция требует использовать конкретные факты об адресате и связать с ними предложение. Тема и текст по умолчанию в этот запрос не передаются. Только при отсутствии описания используются подстановки в резервный шаблон без обращения к LLM: `{company}`, `{city}`, `{industry}`, `{website}`, `{description}`. Готовые черновики можно менять вручную. Генерация не отправляет письма.
5. Прочитайте письма, сохраните исправления, выберите адресатов галочками или кнопкой **Выделить все**. Выбор всех действует на текущий фильтр и поиск. Компанию без email сначала исправьте в редакторе.
6. Нажмите **Отправить выбранные → Подтвердить → Да, точно подтверждаю**. Отправка начинается только после последней кнопки. Изменение текста или SMTP-настроек отменяет старое подтверждение. Подтверждение действует 5 минут и однократно.

### Вложения

В редакторе письма есть блок **Вложения → Прикрепить**. Для добавления одних и тех же файлов сразу к нескольким компаниям выделите их галочками и нажмите **Прикрепить файлы** внизу списка. Вложения сохраняются сразу; текст перед добавлением файлов нужно сохранить кнопкой **Сохранить письмо**. При генерации нового текста уже прикреплённые файлы остаются.

Файл можно скачать нажатием на его название или удалить крестиком. Ограничения: **10 МБ на файл, 15 МБ суммарно и до 20 файлов на письмо**. Общий объём уникальных файлов в проекте — до 100 МБ. Один файл, прикреплённый многим компаниям, хранится в проекте один раз. У отправленных писем вложения доступны для скачивания и не редактируются.

Названия вложений показаны в подтверждении отправки. Добавление или удаление файла после подтверждения требует начать подтверждение заново. Обычное письмо с несколькими адресатами отправляется одной SMTP-транзакцией; если до передачи сообщения отклонён хотя бы один адресат, письмо не передаётся никому из этого списка. Письма компаниям отправляются отдельно каждому адресату.

Ошибки SMTP окрашивают место галочки красным; отправленные письма — серым и недоступны для выбора. Есть фильтры **Не отправлены / Отправлены / С ошибками**. У каждой ошибки видна причина; после исправления можно повторить отправку с двумя новыми подтверждениями. Ошибки генерации показаны отдельно у компании и в сводке, предыдущий черновик при этом сохраняется и не выдаётся за новый результат. Метки различают **✦ DeepSeek**, **Шаблон · нет описания** и **Вручную**. Дословная копия резервного текста от DeepSeek отклоняется как ошибка персонализации; смысловую уместность письма проверяет пользователь.

Отправка последовательная, с паузой в секунду; **Остановить очередь** прекращает работу после текущего письма или запроса генерации. Провайдер может устанавливать собственные лимиты. Статус «Отправлено» означает, что SMTP-сервер принял письмо; попадание во входящие или прочтение получателем он не подтверждает.

Если соединение оборвалось после передачи письма или приложение закрылось во время отправки, результат может быть неизвестен. Автоповтора нет: сначала проверьте доставку у почтового провайдера. Только если письмо точно не принято, нажмите **Проверил: письмо не принято**, затем повторите отправку. Гарантировать единственную доставку при обрыве SMTP невозможно.

## Обмен между людьми

**Экспорт → Проект с вложениями · JSON** сохраняет компании, обычные письма, списки получателей, описания, черновики, сами файлы вложений, шаблон, статусы, даты и идентификаторы отправки. Отдельно копировать вложения не нужно. Максимальный размер импортируемого JSON — 180 МБ.

Импорт объединяет компании по email (для строк без email — по названию), обычные письма — по постоянному идентификатору. Черновики и вложения из импортируемого проекта обновляют существующие неотправленные письма; отправленные и письма с неопределённым результатом защищены от сброса. Повторная загрузка CSV не сбрасывает отправленные письма. Из импортируемого JSON также загружается шаблон.

Версия 1.1 использует формат проекта 2 и открывает проекты старого формата 1. При первом обновлении локального проекта сохраняется исходная копия `project-v1.backup.json`. Для передачи нового проекта с вложениями коллегам они тоже должны обновить приложение до 1.1.

**Экспорт → Отчёт CSV** подходит для просмотра в таблице и содержит названия вложений. Самих файлов в CSV нет. Для полноценного переноса статусов, текстов и файлов обратно в приложение используйте JSON: импорт CSV считывает исходные данные компаний, а не историю рассылки.

Важное ограничение: независимые копии JSON не синхронизируются. Если два человека работают параллельно с копиями, они могут отправить повторные письма. Передавайте актуальный проект по очереди или объединяйте результаты до следующей отправки. Для одновременной работы потребуется общая серверная база.

Данные хранятся автоматически в пользовательской папке настроек `MailDesk`:

- Windows: `%AppData%\MailDesk`.
- macOS: `~/Library/Application Support/MailDesk`.
- Linux: `~/.config/MailDesk` (или `$XDG_CONFIG_HOME/MailDesk`).

`project.json` содержит рабочую базу. `credentials.json` содержит локальные подключения. Они находятся отдельно от исполняемого файла и не теряются при обновлении приложения. Пароли не возвращаются в интерфейс и не попадают в проект JSON/отчёт CSV. На новом компьютере без персонального файла подключения нужно ввести свои данные.

## Разработка

Код использует только стандартную библиотеку Go, зависимости пакетов отсутствуют. Требуется Go 1.24 или новее.

```sh
go test -race ./...
go build -o dist/maildesk .
./dist/maildesk --no-browser --port 8765 \
  --data-dir /workspace/smtp-send-script-local/app \
  --env-file /workspace/smtp-send-script-local/.env \
  --import /workspace/smtp-send-script-local/companies.csv \
  --test-recipient ddkritsin@gmail.com
```

Во время разработки и тестирования реальная отправка разрешена пользователем **только на `ddkritsin@gmail.com`**. Не отключайте `--test-recipient` при проверке. Проверять доставку на адреса компаний запрещено. Протокольные тесты используют локальные имитаторы SMTP и DeepSeek.

`--port 0` (по умолчанию) выбирает свободный порт; адрес автоматически открывается в браузере. Повторный запуск с той же папкой данных открывает уже работающий экземпляр. `--no-browser` выводит адрес в терминал. Флаг `--env-file` загружает локальные переменные, не перезаписывая уже заданные переменные процесса; сохранённые в приложении настройки имеют приоритет над ними.

Сборка всех платформ (нужны Go и Python только разработчику):

```sh
python3 scripts/build.py
```

Для готовых Mac-пакетов выполняйте сборку на macOS: скрипт подписывает весь `.app`, включая метаданные и иконку. Кросс-сборка на Linux создаёт Mac-бинарник, но не добавляет подпись пакета. Workflow `web-macos.yml` собирает обе Mac-архитектуры на Mac, проверяет извлечённый ZIP и запускает веб-сервер через Launch Services с пустым тестовым профилем. Проверяется настоящий локальный запрос к серверу; реальные письма не отправляются. У веб-приложения отдельный идентификатор `local.maildesk.web`, чтобы macOS различала его с нативной версией.

Дополнительная проверка интерфейса (разработчику нужны Playwright, Chromium и OpenSSL):

```sh
python3 scripts/browser_smoke.py
```

Она проходит полный сценарий с доверенным локальным TLS-сертификатом и локальным SMTP: импорт, шаблон, вложения компаниям, обычное письмо, несколько адресатов, контроль тестового адреса, скачивание/удаление файлов, редактирование, два подтверждения, ошибка, повтор, серый статус, фильтры, перенос проекта с файлами и мобильный экран. Во внешний SMTP она не подключается.

Реальные SMTP/DeepSeek требуют сетевого доступа и действительных учётных данных. В управляемом облаке DeepSeek может потребовать разрешения `api.deepseek.com`, а SMTP — TCP-доступа к `smtp.mail.ru:465`; HTTPS-список разрешённых доменов сам по себе SMTP не разрешает. Готовые настольные приложения используют обычное соединение с компьютера пользователя.
